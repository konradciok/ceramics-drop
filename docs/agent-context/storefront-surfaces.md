### Storefront Surfaces

All storefront routes live under `src/app/[locale]/`. Route groups: `(collections)` (grids, has `loading.tsx`) and `(pdp)` (product pages, no `loading.tsx`).

- **Homepage** (`/`) — CMS-managed full-bleed hero (`page:home` document, admin editor `HomeHeroEditor.tsx`; see the CMS content layer in [product-registry.md](product-registry.md)) with a fallback to committed static images/copy when unpublished, plus a daily-rotated fine-art-print rail (`src/lib/print-rotation.ts`, seeded shuffle so the same tiles show all day). `force-dynamic` like other public catalog consumers.
- **Collection pages** — one per ceramic category (`/{category}`), grouped grids of tiles.
- **`/sklep` shop** — the fine-art-print shop: one filterable grid of every published design (`src/app/[locale]/(collections)/sklep/page.tsx` → `PrintShop` client island). Sort (featured / new / collection) and colour + collection filters live in the query string (`?sort=&kolor=&kolekcja=`, parsed by `parseShopView` in `src/lib/print-shop.ts`; the server renders the requested view, the island re-applies the same pure `applyShopView()`); the canonical is always plain `/sklep`. The full list is always in the HTML (crawlable PDP links). Cards show a framed mockup, an on-hover room shot (`editorialGallery[0]`, fetched on first hover), *New* / *Artist's pick* badges and a `+` that opens `PrintQuickAdd` — a native `<dialog>` wrapping the PDP's own `PrintConfigurator` (variant gating from the batched `getUsableVariantKeysByProduct()`, fail-open like the PDP; `/api/checkout` stays the hard gate). A trust + price-ladder strip (`PrintShopStrip`, values from `PrintPricingConfig`) sits above the grid. Merchandising data is static JSON in `config/print-shop.json` (colour families per design, `featured` ids, `newCount`) — colours are seeded by `npm run print-assets:facets` and a CI test fails while a published design has none. The nav Shop link points here. Ceramics keep their own category routes.
- **`/kolekcje` hub + `/kolekcje/{slug}`** — the collection layer. The hub (`src/app/[locale]/kolekcje/page.tsx`) is an editorial gateway (cover, name, count, one-sentence teaser; no prices); each collection page lists that collection's prints with its CMS description. Both live directly under `[locale]/` (not in `(collections)`, whose `loading.tsx` would turn `notFound()` into a 200). A collection page is indexable only when it has a real description in that locale (≥80 chars — the backfill seeds a `<name>.` placeholder) **and** ≥3 published prints; otherwise `noindex,follow` and no sitemap entry (`resolvePrintCollectionPage` in `src/lib/print-collections.ts`). Collection membership/copy come from `loadPrintCollectionDefinitions()` (CMS `description` fields per locale). The page header shows the description's first sentence as the `lead` and the rest as a body paragraph beside it (`splitCollectionDescription`); the meta description is cut at a sentence boundary within 155 chars (`collectionMetaDescription`), never mid-sentence. Approved collection copy is bulk-imported with `npm run collections:import-descriptions` (see Commands). Print PDP breadcrumbs run Home › Collections › {collection} › print.
- **`/fine-art-prints`** — legacy entry that 308-redirects to `/sklep` (`next.config.ts`); print PDPs keep their `/fine-art-prints/{id}` permalinks. `fine-art-prints` is a `CategorySlug` deliberately kept out of `CATEGORY_ORDER` so it never renders through ceramic paths.
- **`/showroom`** — pieces retired from a past drop into showroom state (visible, not purchasable — see `piece_state.showroom` in [database-schema.md](database-schema.md)); visitors can register interest via `/api/interest` (see [api-routes.md](api-routes.md)).
- **Individual product pages** — `/{category}/{id}` (e.g. `/kubki/k01`) in the `(pdp)` route group; the same group also serves print PDPs. Indexable URLs with SEO metadata, `Product` + `BreadcrumbList` JSON-LD, hreflang across all locales, a two-column layout, gallery, specs, add-to-cart island, and a live "more from this collection" strip. The `(pdp)` group deliberately has **no** `loading.tsx` so `notFound()` returns a real HTTP 404 (a parent Suspense boundary otherwise forces 200).
- **Lightbox** — quick-view modal on tiles; links to the product page permalink. Product photos always render at natural ratio, never cropped.
- **`/konto`** — customer accounts via **server-only Supabase Auth** (sessions are httpOnly cookies, verified locally with jose against the project JWKS — no browser Supabase client, no `NEXT_PUBLIC_*` key). Provider state (which sign-ins are live/enabled) is tracked in `docs/STATUS.md`; provider setup, Apple secret rotation, and the deletion runbook are in `docs/customer-accounts-runbook.md` (§1.3/§1.4 for Apple). Order history plus per-order detail/tracking at `/konto/zamowienia/[id]` (ownership-filtered, 404 on mismatch). Both pages `force-dynamic` + noindex; the header `Konto` link is deliberately **static** (session-aware rendering there would flip the prerenderable `pl` tree dynamic). Fail-closed behind the `SUPABASE_PUBLISHABLE_KEY` secret: unset ⇒ pages render "accounts unavailable" and `/api/auth/*` 404. Plan: `docs/plans/customer-accounts.md`.
