# Other API Routes

> Moved verbatim from `AGENTS.md` (context-diet restructure). `AGENTS.md` keeps a short stub with the invariants; this file holds the full detail. Perishable feature state lives in `docs/STATUS.md`.

### Other API Routes

Beyond `checkout` and `stripe/webhook`, `src/app/api/` exposes:
- **`/api/inventory`** — live sold/reserved IDs for client-side cart reconciliation.
- **`/api/interest`** — anonymous, rate-limited (10/min/IP) showroom-interest capture; writes to `product_interest`, always answers `200 { ok: true }` regardless of new/duplicate so submission history is never leaked.
- **`/api/feed/google`** + **`/api/feed/meta`** — Google Shopping & Meta Catalog product feeds, **fine-art prints only**: one row per published design per locale, `g:id` = design id (`fapNNN`), always `in stock` (print-on-demand). `FEED_LOCALES` in `src/lib/feed.ts` covers all 4 locales; PLN for `pl`, **GBP for `en`** (shipped to `GB`), EUR for `es`/`de`. Feeds have no per-visitor session, so `en` is fixed to GBP/GB regardless of any visitor's `currency_pref` cookie (see § Internationalization). `SHIPPING_COUNTRY` in `src/lib/feed.ts` is the shared per-locale market map — `src/lib/seo/structured-data.ts` reads it too, so the `en` print PDP's `Offer.priceCurrency`/`shippingDetails` agree with the feed (Google Merchant Center disapproves a feed↔landing-page price/currency mismatch); ceramic Offers also pick up the `GB` shipping destination from the same shared map, but stay EUR-priced for `en` — ceramics are not in the feed, so there is no parity requirement to satisfy for them. **Ceramics are deliberately excluded from the feed itself.** Each piece is one-of-a-kind, so a piece sold minutes after a fetch stays advertised until the platform's next scheduled fetch (daily at best) — an availability mismatch by construction, not a tunable bug. Consequence, decided and accepted (owner, 2026-09-21): ceramic `content_ids`/`item_id` values still emitted by the pixel + CAPI (`src/lib/analytics.ts`) no longer resolve to a catalogue row. The studio runs no Meta catalogue / dynamic product ads for ceramics, which are the only surfaces needing a catalogue match; ceramic events still carry `value` + `currency`, so conversion reporting is unaffected. Reopen only if catalogue-backed ceramic ads are ever wanted — that reopens the feed decision, not the analytics one.
- **`/api/private-sale`** — resolves a single-use token to re-offer already-**sold** pieces to a specific buyer. Tokens are minted with `npm run private-sale:create`, stored in `private_sales`, and reserved atomically by `reserve_private_sale_pieces()`. Private-sale links are **ceramics-only** — checkout rejects a token combined with prints (`400 private_sale_prints_unsupported`). Spec: `docs/plans/private-sale-cart-link.md`.
- **`/api/promo/validate`** — rate-limited, read-only preview of a promo code's discount for the current cart + currency (no DB writes, no reservation, no claim); `/api/checkout` re-validates authoritatively. See `docs/promo-codes.md`.
- **`/api/returns`** — retired (PR #295, 2026-09-09): `POST` always answers a static `410 { error: 'return_labels_retired' }` with contact info from `src/lib/returns-policy.ts`; no order lookup, label, or email is created. Customers are directed to `ReturnRequestForm.tsx`'s `mailto:` link instead.
- **`/api/newsletter`** + **`/api/newsletter/confirm`** — stateless newsletter double opt-in backed by Resend (`src/lib/newsletter.ts`). POST validates + rate-limits, mints an HMAC confirm token (`NEWSLETTER_CONFIRM_SECRET`, fail-closed 503 when unset) and emails a localised confirm link; the GET verifies it, creates the Resend contact only then (global `/contacts`, or legacy `/audiences/{id}/contacts` when `RESEND_NEWSLETTER_AUDIENCE_ID` is set), and 302-redirects to the localised, noindex `/newsletter?status=…` landing page. The signup form is a footer client island (`FooterNewsletterForm`).
- **`/api/print-assets/[id]`** — signed high-res print files for Prodigi (see above).
- **`/api/media/[key]`** — public GET/HEAD for CMS-managed site-media (homepage hero images/video); keys are content-addressed (`<sha256>.<ext>`), validated against `src/lib/site-media.ts`'s regexes, served from the `site-media/` prefix in the `PRINT_ASSETS` R2 bucket.
- **`/api/admin/content/media`** — admin-gated site-media upload backing the `page:home` CMS document (see CMS content layer above).
- **`/api/debug/fulfilment-status`** — fail-closed, secret-gated (`FULFILMENT_DEBUG_TOKEN`; 404 unless the token is set, 401 on mismatch) minimal read (`{ fulfilmentStatus, prodigiOrderId }`, no PII) looked up by `?payment_intent=`. Preview-only debug surface for the destructive print-purchase E2E to assert the Stripe→webhook→queue→Prodigi pipeline advanced (audit H-2). The test-side secret is `E2E_FULFILMENT_DEBUG_TOKEN`.
- **`/api/admin/revoke-print-asset`** — emergency-revoke a fulfilment asset (distinct from retire; blocks checkout + returns 410 on the signed route).
- **`/api/webhooks/prodigi/[token]`** — Prodigi status callbacks (see above).
- **`/api/admin/*`** — back-office actions, Cloudflare Access-gated (see Admin above).
- **`/api/inpost/webhook`** + **`/api/resend/webhook`** — delivery-status and email-event receivers; the Resend receiver Sentry-alerts on `bounce`/`complaint`, correlated to the order via `orders.resend_email_id`.
- **`/api/csp-report`** — report-only CSP violation sink (`*.clarity.ms` allowlisted); the report-only → enforce cutover is a pending deploy-time op.
- **`/api/auth/login`** (POST form, rate-limited) / **`/api/auth/callback`** / **`/api/auth/signout`** — customer-account OAuth via Supabase Auth (PKCE; Apple's form_post terminates at Supabase's callback). All fail-closed 404 unless `SUPABASE_PUBLISHABLE_KEY` is set; every cookie-writing response carries the full anti-cache header set. The callback also backfills unclaimed guest orders by verified email (`src/lib/account/link-orders.ts`); `/api/checkout` stamps `orders.user_id` best-effort from the session (auth never blocks payment). Account pages read via `src/lib/account/` server helpers — there are deliberately no `/api/account/*` endpoints.
