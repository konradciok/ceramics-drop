# Other API Routes

> Moved verbatim from `AGENTS.md` (context-diet restructure). `AGENTS.md` keeps a short stub with the invariants; this file holds the full detail. Perishable feature state lives in `docs/STATUS.md`.

### Other API Routes

Beyond `checkout` and `stripe/webhook`, `src/app/api/` exposes:
- **`/api/inventory`** — live sold/reserved IDs for client-side cart reconciliation.
- **`/api/cart-lines`** — `GET ?ids=&locale=` resolves cart tokens (ceramic ids, `giftcard:<tier>`) to display line data via `src/lib/cart-lines-server.ts`; display only — `validateCart()` at checkout stays the authority. A retired `print:` token resolves to an unavailable line.
- **`/api/gift-cards/balance`** — rate-limited gift-card balance lookup (`503 gift_card_unavailable` while spending is disabled in `gift_card_settings`). See `docs/gift-card-balance-runbook.md`.
- **`/api/interest`** — anonymous, rate-limited (10/min/IP) showroom-interest capture; writes to `product_interest`, always answers `200 { ok: true }` regardless of new/duplicate so submission history is never leaked.
- **`/api/feed/google`** + **`/api/feed/meta`** — **retired (2026-11-21): a static `410`.** They only ever listed fine-art prints, which moved to their own shop (https://anna-ciok.com); the Merchant Center / Meta Catalog data sources pointing at them should be removed. **Ceramics stay deliberately out of any feed:** each piece is one-of-a-kind, so a piece sold minutes after a fetch stays advertised until the platform's next scheduled fetch — an availability mismatch by construction. Consequence, decided and accepted (owner, 2026-09-21): ceramic `content_ids`/`item_id` values emitted by the pixel + CAPI (`src/lib/analytics.ts`) do not resolve to a catalogue row; the studio runs no Meta catalogue / dynamic product ads for ceramics, and ceramic events still carry `value` + `currency`, so conversion reporting is unaffected.
- **`/api/private-sale`** — resolves a single-use token to re-offer already-**sold** pieces to a specific buyer. Tokens are minted with `npm run private-sale:create`, stored in `private_sales`, and reserved atomically by `reserve_private_sale_pieces()`. Private-sale links are **ceramics-only** — checkout rejects a token combined with gift cards (`400 private_sale_giftcards_unsupported`). Spec: `docs/plans/private-sale-cart-link.md`.
- **`/api/promo/validate`** — rate-limited, read-only preview of a promo code's discount for the current cart + currency (no DB writes, no reservation, no claim); `/api/checkout` re-validates authoritatively. See `docs/promo-codes.md`.
- **`/api/returns`** — retired (PR #295, 2026-09-09): `POST` always answers a static `410 { error: 'return_labels_retired' }` with contact info from `src/lib/returns-policy.ts`; no order lookup, label, or email is created. Customers are directed to `ReturnRequestForm.tsx`'s `mailto:` link instead.
- **`/api/newsletter`** + **`/api/newsletter/confirm`** — stateless newsletter double opt-in backed by Resend (`src/lib/newsletter.ts`). POST validates + rate-limits, mints an HMAC confirm token (`NEWSLETTER_CONFIRM_SECRET`, fail-closed 503 when unset) and emails a localised confirm link; the GET verifies it, creates the Resend contact only then (global `/contacts`, or legacy `/audiences/{id}/contacts` when `RESEND_NEWSLETTER_AUDIENCE_ID` is set), and 302-redirects to the localised, noindex `/newsletter?status=…` landing page. The signup form is a footer client island (`FooterNewsletterForm`).
- **`/api/media/[key]`** — public GET/HEAD for CMS-managed site-media (homepage hero images/video); keys are content-addressed (`<sha256>.<ext>`), validated against `src/lib/site-media.ts`'s regexes, served from the `site-media/` prefix in the `PRINT_ASSETS` R2 bucket (the binding name is historical — the bucket no longer serves print files).
- **`/api/admin/content/media`** — admin-gated site-media upload backing the `page:home` CMS document (see the CMS content layer in [product-registry.md](product-registry.md)).
- **`/api/admin/*`** — back-office actions, Cloudflare Access-gated (see [admin-cms-api.md](admin-cms-api.md)).
- **`/api/sendcloud/webhook`** — Sendcloud `parcel_status_changed` receiver. It verifies the `Sendcloud-Signature` HMAC-SHA256 of the raw body with `SENDCLOUD_WEBHOOK_SIGNATURE_KEY` (401 otherwise) and finds the order by `order_number` (= `orders.id`). It acknowledges unhandled actions with 200 and answers 500 on DB/email failures so Sendcloud retries. Status only moves forward, and the label and customer emails go out once.
- **`/api/inpost/webhook`** + **`/api/resend/webhook`** — delivery-status and email-event receivers; the Resend receiver Sentry-alerts on `bounce`/`complaint`, correlated to the order via `orders.resend_email_id`.
- **`/api/csp-report`** — report-only CSP violation sink (`*.clarity.ms` allowlisted); the report-only → enforce cutover is a pending deploy-time op.
- **`/api/auth/login`** (POST form, rate-limited) / **`/api/auth/callback`** / **`/api/auth/signout`** — customer-account OAuth via Supabase Auth (PKCE; Apple's form_post terminates at Supabase's callback). All fail-closed 404 unless `SUPABASE_PUBLISHABLE_KEY` is set; every cookie-writing response carries the full anti-cache header set. The callback also backfills unclaimed guest orders by verified email (`src/lib/account/link-orders.ts`); `/api/checkout` stamps `orders.user_id` best-effort from the session (auth never blocks payment). Account pages read via `src/lib/account/` server helpers — there are deliberately no `/api/account/*` endpoints.
